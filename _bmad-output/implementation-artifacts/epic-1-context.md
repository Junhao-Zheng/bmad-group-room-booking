# Epic 1 Context: 安全进入并找到可用会议室

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

让课题组成员安全登录、退出，查看会议室及共享日程，并按时段和人数找到可用房间。以预置演示资源形成可独立验收的查询路径，为后续预约和管理功能提供身份、时间及隐私边界；业务规则属于课程原型设计假设，不能表述为真实用户验证结果。

## Stories

- Story 1.1: 使用预置账号安全登录和退出
- Story 1.2: 查看会议室和共享日程
- Story 1.3: 按时段和人数找到可用房间

## Requirements & Constraints

- 初始化至少两个成员和一个管理员；账号唯一、显示名非空、口令至少12字符，演示账号明确标识。重复初始化只补缺失账号，不覆盖既有身份或业务；无注册和账号管理页面。
- 会话自登录起绝对有效8小时，刷新不续期；退出立即撤销当前会话，不影响其他独立会话。错误账号与错误口令统一提示“账号或密码错误”。匿名、过期及退出凭证均不得读取业务；权限必须在服务端执行。
- 目录仅返回房间标识、名称、地点、容量，按名称、地点、标识升序。日程按北京日期与区间相交查询，按开始时间、内部稳定标识升序；仅排除已取消预约和已撤销停用，保留历史及跨日停用。
- 共享预约只暴露房间、活动名、预约人显示名、起止时间和状态，不发送预约ID、用户ID、用途、人数、账号名或取消原因；共享停用可显示时段和原因。白名单同时约束JSON与DOM。
- 查询采用北京时间：当前时刻严格早于开始，结束不晚于当前时刻加30天；同一自然日、整点或半点、30分钟至4小时，次日00:00算跨日。半开区间允许首尾相邻。人数须正整数；合法大于1000返回空结果。可用房间须容量足够且无预约或停用重叠，结果只是查询快照，不保留时段。
- 最终性能验收使用10房间、1000条有效/取消及历史/未来预约，固定种子和基准时间；10个认证客户端预热20次后记录至少200个完整样本，最近秩P95≤1000ms，结果正确且无错误，不剔除慢样本。记录环境及原始证据；认证测试覆盖匿名、到期、退出、两个成员和管理员。

## Technical Decisions

- 采用Flask应用工厂与分层单体，页面/API共用服务，纯规则独立；Python 3.12.14、SQLite 3.53.1、Flask 3.1.3、Jinja2 3.1.6、Werkzeug 3.1.9、Waitress 3.0.2。交付依赖锁、初始化CLI和启动文档；单进程8线程、本地盘WAL、默认仅127.0.0.1。启动检查schema、时区及SQLite≥3.51.3；运行库和私密配置不入Git。表可随故事递增建立。
- 口令使用scrypt:32768:8:1。登录前临时会话有效10分钟；登录在锁外验证口令，短写事务内复核并消费临时会话，轮换随机token与CSRF。数据库只存token的SHA-256摘要。登录/退出仅在提交后签发或清除cookie，失败不覆盖成功并发请求的cookie；认证不写业务审计。
- cookie为HttpOnly、SameSite=Lax；所有POST含登录/退出均检查精确配置Origin与CSRF，拒绝缺失值。认证页和业务GET使用no-store。HTTP只供loopback演示；其他部署须HTTPS及Secure cookie。操作者来自会话，授权先于受保护参数校验。
- 时间存UTC整数秒，统一注入Clock，每次查询捕获一次当前时刻；输入严格为北京时间`YYYY-MM-DDTHH:MM`，不接收偏移或秒。ID限定正SQLite整数范围，拒绝bool、溢出及非规范数值，避免绑定导致500。
- 预约与停用共用记录和1800秒唯一占用槽；查询以单条参数化SELECT结合容量和NOT EXISTS槽获取一致快照，多查询使用短读事务。已结束但未取消记录保留历史槽，夹具必须遵守槽完整性。
- API以`/api`开头，认证使用login/logout/me，查询使用rooms/availability/schedule。成功只包装一层`{ok:true,data:结果}`，列表为`{items,total}`，日程项以`kind`区分两类共享记录。错误统一含code/message/fields/conflicts；非法输入400、未认证401、无权限或CSRF403、不存在404、存储忙503、内部错误500。API不返回登录HTML；错误不泄露凭证、SQL或堆栈。

## UX & Interaction Patterns

顶栏显示项目名、本人显示名、角色和退出。查询表单明确标注北京时间，保留查询条件；房间/日期日程独立成区。未查询、空目录、空日程、无匹配、字段错误、加载及失败分别反馈；失效提示重新登录，不自动提交业务。

采用中文系统字体、正文≥16px、行高1.5；内容≤1120px，桌面/手机留白32/16px；背景#f5f7f8、正文#183343、主色#126d65、错误#a52b37。1280×800及390×844无页面横向溢出。控件具备label、可见键盘焦点与字段提示，反馈使用status/alert，状态包含文字；用户文本仅自动转义或textContent展示。

## Cross-Story Dependencies

按1.1→1.2→1.3推进；预置房间和合规预约/停用夹具使本史诗无需等待管理界面即可验收。后续预约复用身份、时间校验及查询模型，并在提交时重新检查容量和占用；安全与隐私约束随各业务持续验证。
