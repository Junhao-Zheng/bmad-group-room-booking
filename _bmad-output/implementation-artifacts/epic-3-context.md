# Epic 3 Context: 管理会议室、维护停用与操作证据

<!-- Compiled from planning artifacts. Edit freely. Regenerate with compile-epic-context if planning docs change. -->

## Goal

让管理员维护会议室、安排和撤销停用、查询完整业务及操作历史，并证明重启后数据可继续使用。所有管理变更延续预约的一致性与权限规则，保护已有安排，保留可追溯证据。

## Stories

- Story 3.1: 维护房间资料并保护现有容量需求
- Story 3.2: 创建停用并查询完整管理记录
- Story 3.3: 撤销尚未结束的停用
- Story 3.4: 查询操作证据并在重启后继续使用

## Requirements & Constraints

- 房间名称、地点去首尾空白后分别为1—80、1—120字符，容量为1—1000整数；名称与地点组合唯一，修改保留稳定标识。不提供硬删除或永久下线开关。降低容量须保护所有未结束且未取消预约，包括进行中记录；冲突整次拒绝，向管理员列编号、时段、人数。
- 停用起止为北京时间半小时刻度，满足 `t < start < end <= t+30天`，允许跨日和超过4小时。与预约、停用均按半开区间互斥；冲突不得自动取消原安排。创建及撤销原因去空白后为1—500字符。首次撤销仅在结束前；重复撤销仍校验权限与原因，返回原结果，不覆盖元数据。撤销释放占用，不恢复已取消预约，不允许直接编辑停用。
- 管理列表按房间、北京日期、状态过滤，开始时间及标识升序；停用四态为待开始、进行中、已结束、已撤销。审计按对象类型、日期过滤，事件时刻及标识降序。保存真实变更的操作者快照、动作、目标、时刻、前后值及原因；重复操作和无变化更新不增审计。
- 用真实文件库及HTTP验证预约与停用创建、预约创建与降容量各至少20轮竞争，检查最终数据。审计故障必须全量回滚；真实停服重启后比对业务、槽、审计关键字段与关联，旧成功意图仍可重放。未认证、失效会话和普通成员直接调用管理接口均不得改数据。

## Technical Decisions

- 沿用Flask分层单体，服务层为唯一业务写入口。SQLite共用 `reservations` 与以 `(room_id,slot_start)` 唯一的1800秒槽；停用创建者写入 `user_id`，撤销复用取消存储列，对外使用 `revoked_*` 命名。已结束未撤销记录保留历史槽。
- 写入先 `BEGIN IMMEDIATE`，取锁后用统一 `Clock.now_epoch()` 采样一次，再以该时刻复核会话、角色和数据库现状。业务、槽和审计同连接同事务；命令只调用一次 `audit_writer(conn,event)`，writer不另开事务或取时钟。重复及无变化调用零次；异常全部回滚。
- UTC整数秒存储，北京时间展示；输入严格为 `YYYY-MM-DDTHH:MM`。查询日期按区间相交判断，跨日停用在各覆盖日出现。撤销状态优先，否则按当前时间派生状态，无定时任务。
- 管理写入使用POST及精确Origin、CSRF校验。操作者来自会话；先授权再参数校验。JSON整数不接受bool/浮点/数字字符串，ID限正64位整数。文本按Unicode码点计数，去首尾空白后校验，拒绝NUL及无效UTF-8，不合并大小写或Unicode表示。遵守现有白名单DTO及统一成功/错误外层；审计前后值返回对象。列表返回全部匹配的 `items,total`，不自行引入分页。字段非法400、权限403、不存在404、业务冲突409、锁等待超时503、内部故障500；不暴露凭证、SQL或堆栈。
- 本地盘WAL，Waitress单进程8线程；连接独立，启动核验schema和运行时。备份用SQLite backup API；运行数据、备份及凭证不得进入版本库。

## UX & Interaction Patterns

管理员入口提供房间、停用、操作记录管理；时间明确标注北京时间。失败保留输入，容量和占用冲突显示必要详情；撤销需原因与确认，成功刷新占用和列表。分别反馈加载、空结果、提交中、成功、冲突、权限失效及服务失败；重新登录后不自动重提。文本安全转义，控件有label、键盘焦点与反馈区域，状态含文字；桌面及390px手机页面无横向溢出，管理表格可局部横滚。

## Cross-Story Dependencies
