# 课题组预约交互约定

以 PRD 的 UJ-01—UJ-03 和 FR-01—FR-22 为业务依据，时间一律向使用者明确标注“北京时间”。具体请求路径由架构固定。

## 成员预约

登录后选择日期、开始时间、结束时间和预计人数，查询可用房间。空结果与输入错误分开提示；不能把未查询当成没有房间。

选择房间并填写活动名称、用途后提交。提交中禁用重复点击并显示等待，但服务端仍负责幂等。每个新意图生成新标识；相同内容的网络重试沿用标识，实质字段变化后换用新标识。成功显示预约编号和时段；冲突保留输入并提示重新查询。网络响应不确定时，允许使用原意图重试，不能声称预约失败或静默生成新标识。

## 查看与取消

个人记录支持状态筛选，状态依据当前服务器时间。本人待开始记录可以取消，确认后才发送请求；已开始、已结束等情况解释不能取消的原因。取消成功后刷新列表及相关可用性信息。

共享日程仅展示 PRD 允许的字段。不能通过隐藏 HTML 元素或 CSS 来掩盖已经返回给普通成员的他人用途、人数、账号名或取消原因。

## 管理员操作

新增或修改房间均显示字段校验结果；容量降低被拒绝时展示冲突编号与必要信息。

创建停用前输入房间、时间和原因。与预约冲突时列出冲突，保留输入；不自动取消任何已有预约。取消他人预约及撤销停用均需理由并再次确认。历史记录保持可查看，已取消/撤销记录不能再次生成状态转换或改写原原因。

操作记录只对管理员提供入口和数据，按对象类型和日期筛选。错误提示不得展示堆栈、SQL、会话或密码。

## 通用状态

- 首次加载、操作中、空结果、成功、业务冲突、权限失效、服务器失败分别显示明确文字。
- 会话过期提示重新登录，不自动重提未完成的业务写入。
- 所有用户文本按纯文本渲染，不把活动名称或用途插入不安全 HTML。
- 前端检查用于快速反馈；直接调用接口仍执行相同业务与权限校验。

本文件的 final 表示该交互约定可供实施，不代表界面已经实现或人工验收通过。
