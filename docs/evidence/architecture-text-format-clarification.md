# A-ARCH-02：业务文本可存储格式澄清

2026-11-12，在首次业务写故事2.1实施前，由主代理检查并提出。不是人类否决，也不是教师门禁。

触发：既有架构按Unicode codepoint约束长度，SQLite CHECK使用length；实际SQLite3.53.1试验中，Python字符串NUL加X长度为2，SQL length结果为0。孤立代理码点无法编码为UTF-8，可使绑定失败。若不规范格式，符合表面长度的输入可能变为500。

选择：在纯字段规范化阶段拒绝NUL和不合法UTF-8，返回400 INVALID_INPUT及字段提示；普通中文、emoji及HTML仍按原规则接受。否决为控制字符改写数据库长度约束和显示语义，因为本项目字段是供人阅读的活动/房间文字，不需要保留NUL。不改FR时间、权限、长度或互斥承诺。

产物：architecture.md§5.2及Story2.1 Code Map，后续实现与实际拒绝用例验证。此处记录的是AI设计选择，不能加入人工否决计数。应用尚未在此记录时实现业务写入，测试完成后由故事证据回指。
