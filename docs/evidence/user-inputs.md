## 2026-11-13 本人逐项复核补充

### U-07 真实预约现状

用户原文：“课题组现在林老师来安排用房间，然后微信群里通知，登记不知道，有时候会和大组其他导师撞时间。一般组会地点在2号楼407”。

据此确认（用户本人陈述，未独立核实）：林老师安排用房、微信群通知、通常在2号楼407、偶尔与大组其他导师的安排撞时间。是否另有登记未知；没有据此认定无登记制度，也未确认所有相关导师会使用本系统。

这是需求事实补充，不自动计为一次人工否决或方案批准。待讨论：系统是否覆盖共享该房间的大组，或由统一管理者录入其他导师的占用；只记录本课题组预约不能保证避免外部安排冲突。

### U-08 首版保留单课题组范围

用户原文：“先只供本课题组使用，其他组冲突仍人工协调”。

触发：在U-07揭示跨导师用房冲突后，AI建议各导师组指定负责人共用系统登记。用户选择不采用该扩展建议，保留单课题组范围；尚未提供选择依据，下一步补问。此决定发生在开发后复核阶段，不倒填为初始需求决策。当前已回写范围，但暂不计为满足五要素的完整人工决策/否决条目。其他导师未被视为已同意使用；系统一致性保证仅覆盖系统内登记记录。

### U-09 范围选择理由及待澄清的占用规则

用户原文：“因为实验室预约是为了让大组知道，如果别的导师也约了可以让导师们沟通一下，当然先约的话别的导师约不了”。

已知意图：向大组传达用房安排，发生跨导师安排冲突时由导师沟通，先预约者优先。待澄清：“别的导师约不了”是指其他导师或其负责人也在同一系统提交、由系统拒绝重叠预约，还是微信群通知后人工遵守先约先用。前一种涉及扩展U-08已选择的单课题组使用范围；后一种不能宣称软件阻止了系统外预约。

在用户确认前，不代选解释、不改账号权限或功能，不把U-08/U-09包装成已完整验证的人工否决。此前U-08范围文档保留，当前正在澄清其边界。

### U-10 澄清后的最终使用范围

用户原文：“A：其他导师或其负责人也用同一系统预约，重叠时系统自动拒绝”。

U-10结合U-09的理由明确替代U-08的临时选择：同一大组内共同使用房间的导师或负责人使用同一系统；先成功预约的占用阻止重叠预约。U-07—U-10是一次连续澄清，不拆成多次否决。尚未证明各导师实际同意采用；普通学生能否预约、管理员具体人选及其他业务规则继续逐项讨论。完整决定见D-005。
