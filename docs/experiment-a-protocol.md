# 实验 A 预登记协议

状态：protocol-draft。实际实验开始前固定候选故事、基线、提示词和统一评审清单。此文件不包含测量结果。

## 问题与设计

检验在本课程项目及本次任务范围内，额外的需求、架构和项目规则上下文，是否减少返工和规则偏离。X 获得完整规划上下文；Y 仅获得口述需求以及公平提供的最小运行基础。选择难度相当且尚未实现的故事，选择理由在开始前登记。

两个工作目录位于仓库外的实验隔离区。Y 的代理仅允许读取它的目录，不能读取本项目规划、源代码或 X 的产物；新会话并不等于文件隔离，必须同时限制可读输入。共享主机本身不构成强安全沙箱，这一点作为局限披露，并保存实际执行记录核对可见输入。

## 控制条件

- 同一天、同一 Codex 宿主、同一父会话继承的模型配置，不手动更换模型。精确模型标识如不可核验则说明，不猜填。
- 操作方为同一个主代理执行实验协议，用户负责授权；这与课程原设想的同一个学生操作存在差异，报告单列。
- 同一技术运行环境和从同一基线派生的最小接口契约，禁止向对照提供答案或项目规则。每组各一次初始实现请求；修复轮次按实际记录。
- 同一套评审规则、相同断言和边界条件；不刻意削弱 Y 的口述业务需求。完整规划的准备成本与实现/返工成本分开统计。
- 实验代码先保留原始产物和首轮评审记录，再修复。修复前后的文件哈希与差异保留。

## 五项指标的操作定义

| 指标 | 操作定义 |
|---|---|
| 会话轮数 | 实现开始到达到本实验完成标准的独立实现/修复代理调用数；评审调用另列，不混入 |
| 首轮评审通过率 | 首轮统一评审无变更请求记为通过。每组只有一个故事，因此只能为 0% 或 100% |
| project-context 违规数 | 首轮评审命中的不同规则编号数量；同一规则多处违反只计一次，同时保留位置明细 |
| ADR 冲突数 | 首轮评审命中的不同 ADR 编号数量；不是失败测试数 |
| 完成后返工故事数 | 正式判为 done 后又修改的故事数；review 阶段修复不算。若无观察窗，只报告观察范围内数据 |

附加记录初稿耗时、评审耗时、修复耗时和规划阶段记录。只把实际采集的时间作为结果；无法恢复的早期规划投入标为未采集，不能补估成实测。

## 收益与局限

比较两组的实际差异，说明需求、架构和规则中哪些信息解释了差异。对 12 个故事的外推只是情景估算，必须与实测分开；记录规划投入不全时，不给出确定净收益结论。

样本量只有两个、任务难度不完全等价、无随机分配、运行顺序及代理熟悉度可能影响结果，不能推导 BMAD 的一般因果效果。负结果或无差异均照实报告。实验 B 免做，不混入本协议。

## 已选定配对（实施目标之前登记）

- X：Story 2.5 `admin-cancel`，管理员有原因取消未结束预约。
- Y：Story 3.3 `revoke-block`，管理员有原因撤销未结束停用。
- 两者均是对现有记录的单次终态转换，都涉及管理员权限、原因合法性、结束期限、重复操作、槽释放、历史和原子审计；均需同一页面/API适配与测试。主要不同是对象kind和输出取消/撤销字段，因此复杂度接近而非完全相同。
- 共同基线在Sprint1和3.1/3.2完成后固定Git SHA；基线必须同时没有`admin_cancel_booking`和`revoke_block`实现，不能把目标写成现成通用函数只改参数。
- 两组都可见相同必要的运行代码、schema、通用事务/DTO/认证接口及依赖锁。Y不能看到任何PRD、架构、project-context、故事、上游评审或X产物；基线里既有代码本身承载部分上下文，会压小观察差异，作为局限披露。

## 统一首轮评审检查单（冻结后两组同用）

| 检查项 | 相同通过标准 | 规则/ADR |
|---|---|---|
| 身份 | 成员/匿名/到期/退出拒绝；服务事务内重验有效admin | context7/8、ADR05/06 |
| 输入 | reason strip后1—500字符，重复请求也检查；对象kind正确 | context10/13、ADR07 |
| 时间 | 首次只允许t<end；t=end拒绝；已转换重复返回不重新限制结束期限 | context5/10、ADR02/07 |
| 幂等 | 重复保留原actor/time/reason，无新审计，响应同形状 | context10/12、ADR07 |
| 占用与历史 | 仅删对应槽，保留原记录；不恢复其他取消对象 | context4/10、ADR03/07 |
| 原子性 | 业务/槽/审计同BEGIN IMMEDIATE连接；writer一次；注入失败全回滚 | context3/12/14、ADR03/07/08 |
| HTTP与DTO | 正确endpoint、单层ok/data、精确Full DTO和错误码；权限先于对象输入 | context9/13、ADR01/06 |
| UI | 原因、确认、等待/成功/错误清楚；长文本安全，手机可操作 | UX合同及context9 |
| 验证 | 合法路径、权限/期限/重复/并发/回滚测试实际运行；无skip算通过 | context14、ADR08 |

首轮程序按此列表逐项对称检查，不因Y缺上游材料放宽，也不为制造差异挑错。首次结果保存后才揭示完整上下文进行修复。具体违规数量依真实定位证据计，不把所有失败测试直接算作独立违规。
