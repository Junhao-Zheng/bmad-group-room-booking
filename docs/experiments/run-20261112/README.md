## 如何复核

- [预登记协议](../experiment-a-protocol.md)、[共同输入清单](../frozen-inputs/input-manifest.json) 在派发前固定。两组运行代码由共同 Git 基线 `b0ce58a9b66144db5a4b15f61376132fa3f210e4` 提供。
- `originals/X`、`originals/Y` 各自保存不可覆盖的首次源代码压缩包、原始测试/HTTP/截图证据包及每文件 SHA-256。包内没有虚拟环境、node_modules、运行数据库或凭据文件。不要在项目根直接解压；另建临时目录复核。
- [X 逐项判定](uniform-final/X-score.json)、[Y 逐项判定](uniform-final/Y-score.json)、[比较表](uniform-final/comparison.json) 在任何实现修补反馈前保存。
- `uniform-parent-browser` 是父流程对两份封存源代码的实际浏览器复跑，手机成功面板另经目视检查。原始全量回归和真实 HTTP 数据在各自证据包中；父流程验证唯一测试 ID 和报告源文件哈希。
- `initial-X.diff`、`initial-Y.diff` 是各自固定输入至初稿的变更；之后主仓库文档工作不混入实验差异。源文件修改前后哈希一致。

## 检查器修正不是产品修复

原检查器直接向两个 service 传 reason 字符串；Y 正当地使用 payload 字典，因此 Y 的锁后单时刻测试先触发输入拒绝。`uniform-review` 保留这一原始失败。修正版只作服务参数适配，接受断言不变；`uniform-service-adapter.diff` 可核对。对两组都重跑同一修正版，17 项均通过，应用没有修改。这个失败不记为 Y 的时间、规则或 ADR 缺陷。

## 规划投入与十二故事情景

可核验的 Git 初始化至史诗规划提交区间为 3,418 秒（56 分 58 秒）；这包括工具和等待，不是主动工时，也不覆盖初始化前和人工投入。两组本次调用与首轮结果相同，没有测得可抵扣这段投入的返工节省。

若仅作机械情景外推，按代理回合时长 Y−X = −81.013 秒，12 个相同差值的故事为 −972.156 秒（约 −16.20 分钟的“节省”，即 X 多用时）；按派发至封存时长则为 −1,329.370 秒（约 −22.16 分钟）。任务不相同、样本各一、未随机和未控负载，故这些数字不是全项目实测或净收益估计，不能与规划区间相加后宣称因果成本。

## 适用范围与后续

同一天、同主机、相同父代理继承配置，无模型覆盖，但精确模型 ID 不可核验。实际操作方为 AI 父代理，不是学生手动运行。X 先 Y 后；X 首次文件名检索列出部分 Y 路径，未报告读取其内容，后续限定 X；隔离为指令约束，不是操作系统沙箱。父流程期间也准备文档和录屏工具，背景负载未控制。Y 可读的基线代码/测试本身携带部分既有约束，可能压小差异。

Y 原浏览器为 1280×900 / 390×900，满足冻结的桌面/手机要求；项目完整故事规定的 1280×800 / 390×844 留给后续统一集成验证。Y 浏览器报告未哈希自身脚本，父流程另外核对整份封存源树未变。未因此伪造实验性能或质量差异。
