# 工作流执行与裁剪说明

用户明确要求“帮我全部完成这个作业后认真检查……新建github仓库上传”，并授权其他业务规则由AI拟定。因此常规菜单、Continue、文档路径、技术选择及实现的逐项确认由AI在授权范围内推进。此裁剪不把AI选择记为人类批准，也不免除测试、评审和真实性要求。

## BMAD阶段

产品简述、PRD和架构使用项目实际安装的BMAD6.12.1工作流及独立评审；故事拆分按四步提取→史诗→故事→验证执行；sprint-planning负责就绪核对与生成版本化状态。实现使用bmad-build的规划、独立实现上下文、差异检查、独立评审和验证。

独立AI代理是隔离的模型上下文，不是多位真实组员。压缩在同一天完成的两轮增量也不是四周真实课堂履历。教师M1/M2、人类决策日志与真实使用反馈只能由相应真实来源提供。

实验A保持相同模型配置/主机/操作者，并分别保存上下文输入、初始代码和统一评审结果。精确模型标识若运行环境未暴露则记为未知，不推测。实验B按用户转述教师意见免做；不擅自推断其评分如何转移。

## 证据边界

文档final=工作流产物完成；story done=其验收及评审完成；二者均不等于课程满分。数据和演示账号均为合成夹具。全程不伪造访谈、人工否决、教师批准或小组分工。

## 实验A与常规质量评审的边界

实验X/Y在独立运行副本中实施，主仓库同时只整理人工清单和录制工具。每组的实现差异由共同Git基线及其派发前固定输入重建，包含该实现副本新增/修改/删除文件；主仓库同期无关的纯文档/录制工具增量不混作某组实现结果。两组初稿均封存后才用相同rubric评审；三镜头质量评审和后续集成另列。主仓库故事的状态基线与实验共同运行基线分别保存，不能篡改成同一个提交号。

输入隔离是指令约束。X实现者报告第一次文件名清单越过了目录边界，看到部分Y路径，但未读取其文件内容；后续工作留在X。将这一事实作为实验局限披露，不把路径清单冒充强安全隔离证明，也不把它直接计作产品代码的project-context违规。

用户已明确把人工判断集中在最后处理，见[最终人工清单](final-human-tasks.md)。开发中的“继续”和后续自动化完成不计为规则确认、人工否决或教师门禁。
